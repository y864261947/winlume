REIZO / PRODUCTION LAUNCH PLAN

正式上线目标计划

目标不是“页面全部完成”，而是在可控风险下发布一个能让个人用户真实使用、让企业客户真实留资、让团队能观测和回滚的 Reizo 1.0。计划以 T0 为启动日，建议按 6 周执行；任何关键验收未通过，上线日期顺延。

版本：1.0 正式上线计划周期：T0 → T0+6 周范围：个人版、企业版、账户、new-api、部署状态：待进入上线验收阶段
上线定义范围现状与缺口6 周计划验收标准发布与回滚30 天指标

1. 正式上线的定义

以下四项必须同时成立，才将版本标记为“正式上线”。任一项不成立，最多只能称为公开测试版。

A / USER

个人能完成真实任务

新用户可注册、进入工作台、调用模型或应用、看到结果与用量、管理 API Key。

B / BUSINESS

企业能留下有效线索

AI 评估与咨询入口必须真实提交、分配负责人、可追踪状态、可回复客户。

C / OPERATIONS

团队能知道发生什么

错误、延迟、调用、用量、注册、线索与部署均有可查看的记录或告警。

D / SAFETY

团队能安全停止问题

具备备份、回滚、密钥管理、权限边界与关键故障降级方案。

3. 当前现状与上线缺口

当前 UI 和门户已经较完整；上线风险集中在“真实数据一致性”“异常路径”“企业线索运营”三处。

模块当前状态上线前必须补齐风险等级
个人门户与目录页面已完成搜索空结果、无登录状态、卡片跳工作台、模型/价格数据一致性回归。中
工作台调用主体已接入完成从模型选择到结果、失败、重试、产物保存、用量扣除的端到端测试。高
账户 / API Key / 用量new-api 已接入注册、登录、Key 创建/撤销、鉴权、团队隔离、余额不足、账单一致性测试。高
公开计费页页面已完成明确展示价格是否读取实时规则；若不是，必须醒目标注参考性质并避免与真实扣费冲突。中
企业门户页面已完成替换为可公开使用的案例/图片/文案；CTA 进入真实表单和通知流程。中
企业评估与咨询表单已有线索入库、通知负责人、自动回执、后台查看、状态流转、隐私告知。高
部署与可观测性自动部署可用确认生产环境变量、数据库备份、健康检查、错误日志、发布失败回滚和告警责任人。高

4. 六周上线计划（T0 为启动日）

每周末必须举行上线评审。若红色验收项未关闭，不进入下一阶段。

T0 → T0+5
基线冻结

第 0 周：确定可上线范围与负责人

冻结 1.0 范围、配置生产环境、建立单一问题清单和每日同步机制。

  • 个人/企业主要路由与门户页面已存在。
  • 确认正式品牌、域名、隐私政策、服务条款、客服渠道、企业案例授权。
  • 指定产品负责人、技术负责人、运维值班负责人、企业线索负责人。
  • 定义是否允许真实充值；若不允许，所有相关入口必须改为测试/咨询口径。
T0+1 周
核心闭环

第 1 周：个人账号、调用与计费闭环

用全新账户完成最小真实体验，并将每一个失败状态转化为明确反馈。

  • 注册 → 登录 → 进入工作台 → 选择模型或应用 → 发起调用 → 查看结果。
  • 创建 API Key → 使用 Key 请求 /v1/models 与一个聊天/生成接口 → 撤销 Key 后确认访问被拒绝。
  • 核对账户余额、用量明细、工作台记录与 new-api 后台数据是否一致。
  • 覆盖余额不足、上游超时、无可用模型、未登录、Token 无效、网络断开等失败路径。
T0+2 周
数据与安全

第 2 周：数据一致性、权限与隐私

把用户看到的数据、后台数据和实际扣费规则对齐，并关掉明显的权限风险。

  • 统一模型目录、公开价格、工作台可选模型和真实扣费来源；差异须有产品说明。
  • 检查 API Key 只可访问本人/本团队资源；团队成员、管理员与普通成员权限符合预期。
  • 验证日志不输出密码、Token、完整 API Key、用户敏感表单内容。
  • 添加隐私政策、服务条款、企业评估数据用途与保留时长说明。
T0+3 周
企业转化

第 3 周：企业评估与咨询线索闭环

让企业页从“展示”变成可衡量的获客入口。

  • AI 评估表单提交后写入数据库或 CRM，生成唯一线索编号与时间戳。
  • 邮件/企业微信/飞书等渠道通知负责人；客户收到“已收到，何时回复”的确认。
  • 线索至少具备：新建、已联系、需求澄清、方案中、赢单/失单状态。
  • 为案例、咨询、评估 CTA 添加来源标记，能够统计来自哪个页面。
T0+4 周
灰度验收

第 4 周：内部测试与小范围灰度

内部人员和受邀用户使用真实账号、真实额度测试，不直接将所有流量导入。

  • 邀请 10–20 位内测用户：创作者、开发者、企业联系人各至少 3 位。
  • 记录每次任务的成功率、首屏时间、模型调用失败原因、关键页面流失点。
  • 修复 P0/P1：不能注册/登录、不能调用、Key 泄露/越权、计费错误、表单丢失、服务不可用。
  • 完成手机端、主流浏览器和低网速环境的回归。
T0+5 周
上线演练

第 5 周：发布演练、备份与回滚

在正式发布前演练一次故障恢复，而不是只验证正常发布。

  • 备份数据库并实际执行一次恢复演练；记录恢复时间和负责人。
  • 从上一稳定版本回滚一次应用；验证健康检查、登录、调用与数据库兼容。
  • 确认监控面板、错误告警、服务日志、new-api 可用性和第三方依赖状态。
  • 发布窗口、公告文案、客服排班、故障群组和升级路径全部确定。
T0+6 周
正式发布

第 6 周：逐级放量与上线后值守

采用可回退的放量，不以“一次全量”作为唯一发布方式。

  • 先内部账号 → 受邀用户 → 10% 外部流量 → 50% → 全量；每一级至少观察 2–4 小时。
  • 观察错误率、登录成功率、模型调用成功率、P95 延迟、余额/账单异常、企业线索接收率。
  • 如达到回滚阈值，立即停止放量并回滚，不等待下一个工作日。

5. 正式上线验收标准

所有“必须”项均需在生产或与生产等价环境留存测试记录。建议每项包含：测试账号、时间、操作步骤、截图/日志、结论和负责人。

个人版必须通过

  • 新用户注册、登录、登出与会话续期正常。
  • 工作台至少一条文本模型和一条非文本能力可稳定完成真实调用。
  • 创建、展示、复制、撤销 API Key 正常；撤销后请求立即失效。
  • 模型目录、工作台模型和实际可调用模型一致，或明确标注不可用原因。
  • 调用结果、调用记录、账户用量、余额变化的账单口径可解释。
  • 未登录、无权限、余额不足、上游失败都有可理解且可行动的提示。

企业版必须通过

  • 企业导航、案例、部署、咨询与 AI 评估页面无死链。
  • 评估/咨询提交后客户收到确认，负责人收到通知，线索可在后台查看。
  • 线索数据具有最小权限控制，未经授权者不能查看客户联系方式或评估内容。
  • 页面中使用的客户名称、案例数据、标识和效果数字有公开授权或明确为示例。
  • 企业 CTA 的来源能被统计，能够计算评估页提交转化率。

平台与安全必须通过

  • 生产环境密钥只存在于受控环境变量或密钥系统，不提交到仓库、不写入前端。
  • new-api 不可用、数据库不可用、上游模型失败时服务有明确降级和日志。
  • 数据库迁移在部署中可重复执行；失败不会使应用与数据库版本错配。
  • 存在最近可用的数据备份；恢复演练已完成。
  • 健康检查、错误日志与告警渠道可用，并指定第一响应人。

体验与合规必须通过

  • 桌面端和移动端关键路径均完成回归。
  • 页面加载、按钮状态、表单错误、空状态和焦点可用性无明显阻断问题。
  • 公开页具备服务条款、隐私政策、计费说明、联系/投诉方式。
  • 对“演示价格”“测试额度”“能力限制”做真实、清晰且不误导的说明。

7. 上线后 30 天目标

先验证留存、使用与线索质量，再扩大功能范围。下列数字是建议目标，发布前应根据预算、模型成本和获客渠道调整。

PERSONAL

激活率

新注册用户中，完成至少一次工作台调用或创建 API Key 的比例 ≥ 35%。

RELIABILITY

稳定性

工作台/API 关键调用成功率 ≥ 95%；登录成功率 ≥ 98%；P95 响应时间有持续记录。

BUSINESS

企业线索

每周获得可联系的企业评估/咨询线索；100% 线索在 1 个工作日内首次响应。

BILLING

计费可信度

0 起无法解释的高优先级余额/用量差异；所有差异在 1 个工作日内完成定位。

SUPPORT

支持效率

高优先级工单首次响应 ≤ 2 小时；常见问题沉淀至文档或产品提示。

LEARNING

产品反馈

每周复盘一次：用户最常用能力、首次失败环节、企业咨询来源与流失步骤。

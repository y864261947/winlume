企业版目标执行规划

负责人 B 的目标是把现有企业品牌门户转为可运营的企业获客入口：企业客户能够理解能力、提交评估或咨询、收到确认；团队能够看到线索、分配负责人、记录跟进并输出下一步方案。B 不负责重做个人账号和 API 底座，但要使用 A 提供的安全接口与发布标准。

建议负责人：开发者 B计划周期：T0 → T0+6 周主线：企业线索与方案转化协作依赖：账户 / 通知 / 发布最终产出：可运营的企业获客 1.0

一、职责边界

B 对企业版页面、企业表单、线索数据、通知、跟进状态、案例可信度和企业发布验收负责。B 不应单独改动登录、Key、计费或 new-api 核心逻辑；涉及共享平台的改变需与 A 共同评审。

PRIMARY

企业获客门户

企业首页、能力、案例、部署方向、咨询专员、AI 评估页的内容、交互、CTA 和移动端体验。

CONVERSION

线索与咨询闭环

评估/咨询表单、入库、客户确认、负责人通知、状态流转、来源归因与后台查看。

CONTENT TRUST

可信企业内容

案例授权、成果指标口径、部署边界、服务流程、隐私说明和企业沟通材料。

三、企业线索最小数据模型

不必先建设完整 CRM，但必须有可追踪的最小闭环。B 可先使用项目数据库或已批准的 CRM；接口和权限必须由 A 参与评审。

线索记录必填字段

  • 线索编号、创建时间、来源页面、UTM/渠道。
  • 企业名称、联系人、联系方式、职位（仅收集必要信息）。
  • 场景描述、行业、系统/数据现状、期望目标、预算/时间意向（可选）。
  • 提交内容、隐私授权版本、提交 IP/防滥用信息（按合规规则保存）。

线索状态与动作

  • 新建：自动通知负责人，24 小时内首次响应。
  • 已联系：记录联系人、时间与沟通摘要。
  • 需求澄清：整理场景、约束、数据边界和试点目标。
  • 方案中：输出评估/方案文档与下次行动。
  • 赢单 / 失单：记录原因，进入项目或复盘。

四、六周执行拆分

B 的每周成果必须可对外演示或由业务人员实际使用。纯静态页面优化不能替代线索和跟进能力。

T0+1 周

冻结企业信息与 CTA

先解决企业客户最容易产生疑问的内容问题，避免把未确认承诺带到公开页面。

  • 审核企业首页、能力、案例、部署、咨询页所有文案，删除无法证明的效果数字和客户名称。
  • 定义两个主 CTA：AI 机会评估与预约方案沟通；所有页面 CTA 统一进入对应流程。
  • 确定企业线索负责人、响应 SLA、客服/销售通知渠道与隐私联系人。
  • 补全企业页的隐私说明、服务范围、联系邮箱/电话或正式沟通渠道。
T0+2 周

评估与咨询表单落库

把企业评估表单从展示组件变成真实数据入口。

  • 定义最小线索表/CRM 字段、数据校验、反垃圾策略和访问权限。
  • 实现评估和咨询提交：前端校验、服务端校验、写入、失败重试与用户确认页。
  • 提交成功后发送客户回执与负责人通知；通知失败必须记录并可人工补发。
  • 与 A 约定共享认证/通知接口，避免企业页直连敏感服务。
T0+3 周

跟进后台与来源归因

让内部人员不依赖数据库查询或聊天记录来管理企业客户。

  • 实现最小线索列表、详情、负责人、状态、备注和下一次行动时间。
  • 企业内容页 CTA 全部写入来源：主页、案例、部署、咨询或评估。
  • 增加内部筛选：新建、待回复、超时未跟进、方案中、赢单、失单。
  • 建立每周线索复盘模板：数量、来源、行业、意向、响应时间、失单原因。
T0+4 周

案例、方案与可信内容

将企业页从“通用 AI 介绍”升级为有证据、有边界的方案入口。

  • 至少准备 3 个可公开案例；每个包含问题、方案、交付周期、指标口径、客户授权状态。
  • 补齐部署说明：私有化/本地/混合部署的适用条件、数据边界、系统集成、权限与审计。
  • 准备一份提交评估后可发送的《首次沟通资料》或自动生成的评估摘要模板。
  • 确保所有案例 CTA 都能产生可追踪线索。
T0+5 周

内部演练与小范围获客

由真实咨询人员模拟接收并处理线索，验证系统和协作流程。

  • 模拟 10 条不同来源/行业线索：提交、通知、分配、跟进、方案、关闭。
  • 检查个人数据权限：非负责人不可读取联系方式或完整评估内容。
  • 邀请 3–5 位企业联系人测试评估流程，记录理解障碍和表单流失。
  • 和 A 一起完成部署、错误日志、表单失败与回滚的联合演练。
T0+6 周

企业版正式发布与运营值守

企业页可与个人版同步发布，但获客放量要服从负责人可响应能力。

  • 先将企业入口开放给已有联系人和合作渠道，确认线索闭环后再扩大投放。
  • 发布后每日检查：新增线索、未读通知、首次响应时长、表单错误、页面 CTA 转化。
  • 首月每周召开一次销售/产品复盘，优先优化高访问低提交的页面和高提交低转化的环节。

五、B 的验收门槛

必须全部通过

  • 企业导航及所有 CTA 无死链，移动端可操作。
  • 评估/咨询能成功保存、显示确认、通知负责人。
  • 负责人可查看、分配、更新线索状态并留跟进记录。
  • 客户在提交后知道下一步和响应时限。
  • 案例和指标都有授权/示例标注，隐私说明可访问。
  • 所有企业线索来源可被统计，能计算页面→提交转化。
企业版上线决策原则
没有线索入库和负责人通知时，不将“免费评估”“预约沟通”作为公开主 CTA；没有授权的案例不出现真实客户名与成果数字；无法保障响应 SLA 时，公开承诺应改为“提交需求资料”而不是“立即咨询”。
